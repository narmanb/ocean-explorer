# Storm refinement after phone screenshots

This revision on `extreme-storm-seas` follows the storm implementation at
`bf36dd4`. Main is untouched. The original six 256² FFT cascades, independent
crossing swells, mobile/desktop controls, MSAA options and benchmark are retained.

## Behavior changes

- **Original Sunset starts by default**, restoring the sea/lighting parameters
  used before the storm category existed. Calm Ocean remains a separate gentler
  preset. Explicit `?preset=cross` or other preset URLs still work.
- **Measure 15 seconds closes the whole settings panel immediately.** Reopen
  Graphics & Performance after the sample to download its JSON report.
- **Foam is localized to compression and compressed steep crests.** Elevation
  alone no longer injects a white sheet over broad wave faces. Freshness no
  longer counts the same injected foam a second time in coverage. Foam at zero
  disables all surface-foam opacity and bubble tint; crest spindrift is independent.
- **Streak noise has the correct rectangular wrap period**, removing the exact
  fourfold repetition within the detail tile. Wind streaks are broader, warped
  and lower in contrast. The texture remains seamless and generated by the GPU.
- **Slope covariance follows the displaced surface Jacobian**, matching the
  already-transformed mean normal. Storm specular filtering can use more of the
  actual slope variation. This reduces excessively thin highlights without
  removing simulation cascades, reducing wave heights or adding a render pass.
- **Storm clouds retain more horizon coverage and density variation**, with
  stronger cloud-base contrast. Their high-coverage density no longer clips as
  readily to a uniformly opaque ceiling. Original Sunset's storm-free cloud
  parameters remain available.
- **Water-height inversion uses up to 16 iterations**, exits early once within
  2 mm, and retains the best solution if subsequent iterations worsen it. The
  camera rejects samples above 5 cm horizontal residual and holds its last good
  surface/valid neighbors. Startup uses conservative clearance if inversion fails.
  Benchmark JSON now includes a cumulative `probeRejected` sample count.

## Evidence and testing

The phone screenshots showed broad snowy faces and regular surface patterns.
The investigation reproduced these using actual Chromium 153 / SwiftShader GPU
execution. Controlled tests held time, camera, resolution and FFT inputs fixed;
shader substitutions were confined to diagnostic pages.

At 780×360, Cinematic Extreme time 37.0167 s, camera approximately (0,33.482,0),
yaw 0°, pitch −12°, 1× MSAA and spray off:

| Metric | Before | Refined |
|---|---:|---:|
| Visible water pixels with foam mask > 0.5 | 43.72% | 8.49% |
| Visible water pixels with foam mask > 0.9 | 31.00% | 2.60% |
| Mean foam mask with Foam = 0 | nonzero | exactly 0 |
| Streak-channel correlation at quarter-tile shift | 1.000 | 0.127 |
| All six displacement/Jxz layers | reference | bit-identical |

These foam figures are spatial measurements of one startup snapshot, not a
steady-state coverage target. Persistent trails accumulate and move over time.
The camera solution changed by about 0.5 mm in this comparison. Cloud color
changes do not affect the diagnostic foam-mask measurements.

An earlier 16,384-position CPU replay of GPU-readback fields found a worst probe
at X=518.76123, Z=656.63623. The old GPU shader reproduced a 1.9794 m horizontal
residual there and sampled an incorrect height. The revised GPU check must pass
the same 5 cm acceptance threshold as the production camera; the previously failing
GPU sample now has a maximum residual of 0.00156 m across all four probes. A deep
trough check still places the camera at −51.574 m, with maximum residual 0.00132 m. Solver/sample
rejection unit tests include bad center, bad neighbors, all-invalid samples and
nonfinite input, plus startup fallback in both camera modes. An actual GPU test
forces all four inverse residuals invalid to verify free-flight startup also
clears the conservative bound. A second 16,384-position CPU replay with best-solution selection still found 10
goals above the 5 cm threshold, supporting the rejection/fallback guard rather
than a claim that every folded patch now has a unique reliable inverse. This is
not a guarantee of collision at every folded surface.

`npm test` covers 11 automated tests, including source/generated equality, syntax,
settings/statistics helpers, preset transitions, bounds and guarded probe reuse.
The browser suite passes 117 checks, including source and both standalone pages
starting in Original Sunset, measurement auto-close, controls/layouts,
resolution/MSAA, fullscreen, presets, reporting and capability fallbacks. That
suite uses offscreen encoding-only mode: it compiles and validates GPU commands
without submitting them.

Separate actual GPU submissions inspect rendered scenes, all six finite
simulation/derivative layers, the packed-Jacobian invariant, strict probe
residuals and diagnostic foam masks. All five new sea presets, Original Sunset,
the previously failing probe position, a deep trough, and both standalone HTML
outputs are checked. Higher MSAA remains available. Native canvas presentation
is replaced with an offscreen WebGPU texture because this software environment's
shared-image presentation path is unavailable.

To run the additional GPU regressions with external Playwright/WebGPU tooling:

```sh
SEA_PRESET=cinematic SEA_DIAGNOSTICS=1 SEA_OVERRIDES='{"foam":0,"spray":0}' npm run test:render
SEA_PRESET=cinematic SEA_OVERRIDES='{"cam":"518.7612305,3,656.6362305,0,-5.5"}' npm run test:render
```

The diagnostic mode measures fragment foam before tone mapping, tags visible
water pixels using HDR alpha, and checks that streak noise does not repeat at
quarter-tile offsets. It is test instrumentation, not a graphics option.

## Remaining limits

Directional fine waves remain visible; removing every ridge would erase useful
surface detail. The surface is still a height field, so some extreme peaks can
look pointed and cannot overturn or form curling breakers. Clouds are layered
procedural fields rather than volumetric storm cells. Camera guard/readback
latency and ambiguous inverses at folded patches remain model limitations.

The covariance and cloud changes add arithmetic; the bounded solver can perform
more iterations at difficult points and fewer at easy points. No new FFTs,
particle systems, application dependencies or per-frame render targets were
added. There is no measured S25+ speedup or sustained 60 FPS claim. Physical touch,
native Android presentation and sustained performance/thermals require phone
validation. The supplied screenshots are instantaneous readings, not benchmarks.
